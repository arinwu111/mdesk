# mdesk

**自选股事件与决策工作台。**

mdesk 把自选股、未来事件、价格与成交信号、个人计划和数据可信度组织到同一条动线上：

```text
事件 / 行情变化
        ↓
是否触发关注条件
        ↓
是否触发我事先写下的计划
        ↓
重新评估 → 决定行动 → 留下理由
```

它不替代券商行情软件，不预测涨跌，也不自动给出买卖建议。它解决的是个人投资过程中更具体的问题：重要事件不要漏、显著变化能被看见、买卖念头来自事先写下的条件而不是临场冲动。

## 五个日常入口

| 页面 | 回答的问题 |
|---|---|
| 今日行动 | 今天真正需要看什么？ |
| 事件 | 接下来有哪些财报、除息、拆股和公告？ |
| 信号 | 哪些标的越过了价格、波动或成交关注线？ |
| 计划 | 我事先设定的观察、买入或减仓条件有没有触发？ |
| 自选股 | 我的关注范围目前是什么状态？ |

“计划”保存在浏览器本地，不写入仓库，也不包含演示持仓。系统只显示“触发你预设的条件”，最终判断仍由使用者完成。

## 当前信号

- **基期变化**：相对 60 个交易日前累计涨跌达到 ±20%
- **单日跳动**：超过该标的近 120 日波动率折算出的个体关注线
- **成交放大**：当日成交量达到前 20 日均量的 2 倍
- **数据可信度**：来源矛盾、字段失效或采集异常，和市场信号分开显示

固定 20% 回答“和上次认真看它时相比变了多少”；波动率关注线回答“今天的变化是否明显偏离它自己的日常波动”。两者用途不同。

## 数据后台为什么仍然保留

普通投资者不负责修正券商数据。后台校验的作用只有一个：当输入数据发生矛盾时，阻止我基于不可靠数字做判断。

现有后台包括数据校验、复权逻辑、数据覆盖、规则说明、调查记录和规则评估。正常派息、拆股和财报不会要求人工处理；只有派息币种与复权计算不自洽、来源互相冲突或衍生指标失效时，才显示数据提示。

项目目前覆盖 35 只自选标的、两年日线、公司行动和前瞻事件。已发现并保留的代表性案例包括：

- 港股派息币种与数据源复权计算不自洽，隐含倍数约为港币兑美元联系汇率
- 港股半日市成交量缺失，属于市场日历边界而非个股异常
- 固定单日 20% 阈值对高波动标的噪声过大，因此改为按个体历史波动率分层

这些案例是数据可信度基础设施，不再占据产品首页。

## 对财富管理工作的迁移

mdesk 首先是个人真实使用的工具，不虚构客户、RM 或机构持仓。方法可以自然迁移：

| 个人版 | 团队场景 |
|---|---|
| 自选股与标签 | 产品池、产品分类与知识库 |
| 事件日历 | 募集、派息、到期、观察日与材料更新 |
| 信号与优先级 | 按重要性和时效性排列待跟进事项 |
| 个人计划 | 结构化记录条件、理由和下一步 |
| 今日行动 | RM 晨报、产品摘要和事项推进清单 |
| 数据可信度 | 材料生成前的来源与口径提示 |

详细边界见站内“能力迁移”页面。

## 数据与架构

```text
raw_*                    原样采集，保留来源与时间
events_*                 公司行动与前瞻事件
dq_rules / dq_results    后台数据可信度校验
mart_*                   价格、复权与自选股快照
Jinja2 + 静态 HTML        今日行动、事件、信号、计划与详情页
```

主要数据源：

- yfinance：港美股日线、公司行动、基础估值和财报日期
- akshare：用于可重叠区间的第二来源比对
- Nasdaq 公开日历：美股除息与拆股前瞻
- 港交所披露易：港股公告标题与原文链接

免费源不覆盖实时报价、盘口、逐笔、精确资金流和完整机构数据；页面会明确展示这些边界。

## 本地运行

```bash
pip3 install yfinance akshare duckdb pandas jinja2
PYTHONPATH=src python3 -m mdesk.pipeline --render
python3 -m http.server 4173 --directory site
```

修改自选范围：`data/watchlist.csv`
修改后台校验规则：`sql/rules_seed.sql`

行情与提醒仅用于个人研究，不构成任何投资建议。
