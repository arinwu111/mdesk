# mdesk 数据运营 SOP

版本 v1.0　生效日期 2026-08-16　维护人 arinwu

---

## 0. 这份 SOP 管什么

mdesk 是一套自建的港美股行情数据工作台。它不产生投资观点，只保证看到的数字是对的。

这份手册规定谁在什么时间做什么、异常怎么分级、出了问题往哪走。

**一条贯穿全篇的原则：机器负责取数和跑规则，人负责判断和决策。**
下面所有表格里「执行者」为系统的行，都由定时任务自动完成，不需要人工触发；
执行者为人工的行，才是真正需要你坐下来做的事。

## 1. 每日动线

### 1.1 港股盘前　08:30 - 09:00

| 时间 | 执行者 | 动作 | 产出 |
|---|---|---|---|
| 08:30 | 系统 | 采集港股行情、公司行动、披露易公告 | 数据入 raw 层 |
| 08:35 | 系统 | 采集前瞻事件（财报日、美股除息日历） | 数据入 events_calendar |
| 08:40 | 系统 | 重算复权价，执行全部校验规则 | 异常清单更新 |
| 08:45 | 系统 | 重新渲染站点 | 页面更新 |
| **09:00** | **人工** | **打开异常清单，检查 P0** | **盘前确认记录** |
| **09:05** | **人工** | **打开事件日历，确认今日及未来三天的事件** | **事件确认** |

人工这两步合计约 10 分钟，要回答的问题只有两个：

1. 今天有没有 P0 异常。有就当场处理，没有就过。
2. 今天有哪些标的除权除息、出财报、有公告。这些标的的价格跳空是预期内的，不该当成异常。

### 1.2 美股盘后　次日 07:30 - 08:00

| 时间 | 执行者 | 动作 | 产出 |
|---|---|---|---|
| 07:30 | 系统 | 采集美股收盘行情与公司行动 | 数据入 raw 层 |
| 07:40 | 系统 | 重算复权价，执行全部校验规则，渲染站点 | 异常清单更新 |
| **08:00** | **人工** | **逐条判断新增异常的原因，填写处理台账** | **台账更新** |

这是每天最核心的 15 分钟。对每一条新增异常，回答三个问题：

- 这是数据错，还是真实行情？
- 如果是数据错，错在哪一步？
- 该怎么处理？

判断结论用命令写进台账，这一步不能省：

```bash
python3 -m mdesk.handle DQ-CA-001 9988.HK 2025-06-11 --status explained --note "数据源用美元派息金额扣减港币价格，复权价以自算为准"
```

`--status` 四选一：

| 值 | 含义 | 角标变化 |
|---|---|---|
| `explained` | 原因已查明，数字可继续使用 | 红转黄 |
| `fixed` | 已做数据修正 | 红转灰 |
| `ignored` | 确认为正常现象，非异常 | 红转灰 |
| `open` | 退回待查 | 转红 |

**台账是这个系统里唯一无法自动生成的东西，也是它最值钱的部分。**
每条记录都是一次真实的判断，攒上三个月就是一份编不出来的工作记录。

## 2. 异常分级与处理时限

| 级别 | 判定标准 | 处理时限 | 处理方式 |
|---|---|---|---|
| **P0** | 数据明确错误，且会导致下游结论出错 | 当场，不超过当日 | 立即定位根因，修正或切换口径，填台账 |
| **P1** | 数据可疑，或错误影响范围有限 | 三个工作日内 | 记台账排期，逐条查明 |
| **P2** | 已知现象、误报，或影响可忽略 | 每周回顾时统一处理 | 归档观察，累积到一定量再决定是否调规则 |

### 已有规则的级别归属

| 级别 | 规则 |
|---|---|
| P0 | DQ-REF-001 代码有效性、DQ-PRC-001 OHLC 越界、DQ-CA-001 派息与复权不自洽、DQ-CA-002 拆股比例超常理、DQ-CRS-001 跨市场价差、DQ-OPS-001 采集失败 |
| P1 | DQ-REF-002 类型登记、DQ-PRC-002 异常跳空、DQ-PRC-003 个股零成交量、DQ-CA-003 大额派息、DQ-CA-004 复权序列偏离、DQ-FUN-001 市值缺失、DQ-FUN-002 有盈利无 PE |
| P2 | DQ-PRC-004 交易日断档、DQ-PRC-005 全市场成交量缺失、DQ-FUN-003 估值极端值 |

### 升级路径

个人自用阶段没有上级可升，但仍需要一条明确的止损线：

- 同一条 P0 连续三天未能查明原因 → 停止使用该标的的相关字段，在自选股页保持红标，不做任何依赖该字段的判断
- 采集连续两天失败 → 页面顶部的「数据截至」会停在旧日期，看到日期不对先查 `raw_fetch_log`，不要相信页面上的任何数字

## 3. 每周动线　周五约 30 分钟

| 执行者 | 动作 | 产出 |
|---|---|---|
| 人工 | 回顾本周全部异常，找反复出现的同类问题 | 问题归类 |
| 人工 | 把重复出现且规则未覆盖的情况写成新规则 | dq_rules 新增 |
| 人工 | 检查误报率高的规则，调阈值或拆分 | 规则迭代记录 |
| 人工 | 清理 P2 归档区，确认无遗漏 | 台账清理 |

新增规则的做法是在 `sql/rules_seed.sql` 里加一段 INSERT，不需要改任何 Python 代码。
每条规则的 `note` 字段必须写清楚来历：这条规则是因为什么问题才加的。

**这个字段不能省**。半年后回看，这些 note 连起来就是整个项目的演进史，
也是唯一能证明「这些规则是长出来的，不是一次性编出来的」的东西。

---

## 4. 每月动线　月末约 1 小时

| 执行者 | 动作 | 产出 |
|---|---|---|
| 系统 | 汇总本月异常数量、按域与按标的分布、处理时效 | 运营报告页自动生成部分 |
| 人工 | 补写重点问题分析、改进建议、下期计划 | 《数据质量运营报告》 |

报告固定六节：总体情况、异常按域分布、异常按标的分布、本期重点问题、
规则迭代记录、已知缺口与下期计划。前三节和第五节自动生成，第四节和第六节人工补写。

## 5. 年度事项

| 时间 | 动作 | 原因 |
|---|---|---|
| 每年 12 月 | 从港交所公告更新次年半日市日历 | 平安夜、除夕、农历新年前一日只有早市，数据源当天不返回成交量。日期每年变动 |
| 每年 12 月 | 更新港股与美股的假期日历 | 用于区分「正常休市」和「数据缺失」 |
| 每年一次 | 复核跨市场对照关系的存托比例 | ADR 比例会变更，比例错了跨市场校验会全面误报 |

## 6. 已知问题与临时口径

这一节记录当前生效的、与默认口径不同的处理方式。每条都要有出处和复核时间。

### 6.1 阿里巴巴与汇丰的复权价一律以自算为准

**问题**　数据源上报的派息金额是港币，但它计算复权价时扣减的是美元金额，
两者相差 7.847 倍，即港币兑美元的联系汇率。

**影响**　9988.HK 全历史 445 个交易日的复权价偏低最多 2.201%；
0005.HK 最近一次派息后的复权价受影响。

**当前口径**　所有历史涨跌幅、区间收益、波动率计算一律使用 `mart_adj_price.self_adj`，
不使用数据源的 `adj_close`。

**待复核**　汇丰九次派息中只有最近一次（2026-08-13）出错，更早八次正确，
推测是新派息入库时的临时状态。**2026-08-30 复检一次**，验证是否自动修正，结论记入台账。

### 6.2 港股半日市当日不使用成交量

**问题**　平安夜、除夕、农历新年前一日港交所只有早市，数据源当天返回成交量为零。

**当前口径**　这些日期跳过全部成交量相关计算，不计入换手率与量能判断。

**复核**　每年 12 月更新次年半日市日历。

### 6.3 所有分析查询必须走主源视图

**问题**　接入副源 akshare 后，`raw_price_daily` 里同一个 (标的, 交易日) 会有两行。
任何按标的分区的窗口函数若不限定来源，`lag()` 取到的「前一交易日」其实是同一天
另一个源的价格，涨跌幅会被算成接近零，**真实的价格跳空会被静默吃掉**。

**当前口径**　建了视图 `price_primary`（= 主源 yfinance），
所有分析类查询、全部 mart 构建、除跨源域以外的全部规则一律走这个视图。
只有 `DQ-SRC-*` 四条跨源规则和 `DQ-PRC-001` 直接读 `raw_price_daily`。

**加新规则时的检查项**　凡是用到 `lag`、`stddev`、`row_number` 等窗口函数的规则，
确认 FROM 的是 `price_primary` 而不是 `raw_price_daily`。这是接第三个源时最容易重犯的错。

### 6.4 港股副源走新浪链路而非东财

**问题**　akshare 的 `stock_hk_hist`（东方财富）在本机稳定失败，
12 只港股里 8 只报 ProxyError，三次重试全部撞在同一台 `33.push2his.eastmoney.com` 上，
是该主机不可达而非瞬时抖动。

**当前口径**　港股副源改为 `stock_hk_daily`（新浪）优先、东财兜底，12 只全部成功，
收盘价与主源一致。美股副源用 `stock_us_daily`（新浪）。

**复核**　若某天港股副源大面积失败，先看是不是链路问题再怀疑数据，
`DQ-SRC-004` 会把未覆盖的标的列出来。

### 6.5 港股前瞻除净日依赖人工确认

**问题**　Nasdaq 的日历接口只覆盖美股。港股前瞻数据来自披露易公告，
只有标题和 PDF 原文，除净日藏在正文里，本版不做 PDF 解析。

**当前口径**　事件日历的港股公告区按标题关键词做粗筛，
类型标注仅用于挑出值得点开的公告，**不作为事实依据**。
涉及分派、供股、股本变动的公告必须人工打开 PDF 确认日期与比例。

## 7. 常用命令

```bash
python3 -m mdesk.pipeline
```

全链路：采集行情 → 采集前瞻事件 → 重算复权 → 跑规则 → 更新快照 → 渲染站点。定时任务执行这条。

```bash
python3 -m mdesk.pipeline --render
```

只重渲染，不联网。改了模板或刚填完台账时用。

```bash
python3 -m mdesk.pipeline --no-forward
```

跳过前瞻事件采集，省掉披露易那段耗时。

```bash
python3 -m mdesk.handle <规则号> <标的> <业务日> --status explained --note "判断结论"
```

填写处理台账。

## 8. 改自选股

编辑 `data/watchlist.csv` 后重跑全链路即可，不需要改代码。

跨市场对照关系在 `data/cross_listing.csv`，新增对子时注意 `tolerance_pct`：
双重主要上市取 3%，ADR 溢价常态化的取 25%，A+H 溢价属正常现象要放到 60% 以上，
监控的是溢价突变而不是溢价本身。
